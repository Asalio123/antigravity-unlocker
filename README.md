# Antigravity Unlocker для macOS и Linux

Порт популярного Windows-анлокера [confeden/Antigravity](https://github.com/confeden/Antigravity).
Позволяет пользоваться **Google Antigravity** (Desktop-приложение) и **Antigravity IDE** из России — **без VPN и без смены региона Google-аккаунта**.

| Платформа | Скрипт | Статус |
|---|---|---|
| Linux x86_64 (.deb / .rpm / tar.gz) | [`linux/ag_unlocker_linux.sh`](linux/ag_unlocker_linux.sh) | ✅ Desktop 2.11.0 / 2.19.1, IDE 2.5.5 — патч+откат верифицированы |
| macOS 12+ (Apple Silicon / Intel) | [`macos/ag_unlocker_mac.sh`](macos/ag_unlocker_mac.sh) | ✅ Desktop 2.10.0–2.19.1 (полная проверка), IDE 2.5.5 — патч+откат верифицированы |

> Поддерживаются **оба продукта** со страницы [antigravity.google/download](https://antigravity.google/download): Antigravity (Desktop) и standalone Antigravity IDE. Если стоят оба — патчатся оба за один запуск.
>
> Скрипты написаны с нуля на чистом bash, повторяют проверенные методы оригинала.
> Только штатные инструменты системы — никаких зависимостей сверх базовых, ничего не устанавливают.

## Что это и как работает

Google закрыл Antigravity для российских аккаунтов и IP. Анлокер снимает блокировку двумя независимыми механизмами:

### 1. Байтовый патч (клиентская проверка)

В Language Server — бинаре, где живёт вся логика авторизации и тарифов — строка `ineligible` заменяется на `inexigible` (обе ровно по 10 байт).

- Сервер присылает отказ eligibility в JSON, где имя поля — часть формата. Переименовав поле в клиенте, мы делаем так, что клиент **не распознаёт отказ** и продолжает работать.
- Размер файла и структура не меняются, патч полностью обратим (обратная замена возвращает бинарь побайтово в исходное состояние).
- После патча бинарь переподписывается ad-hoc, а весь `.app` — целиком, иначе macOS показывает «Приложение повреждено».
- Desktop v2.4+ (включая 2.19.x) этим и ограничивается: весь auth живёт в Language Server.

### 1б. JS-патч (только IDE)

У standalone IDE часть авторизации живёт в JS-шелле, а не только в Language Server. Скрипт перезаписывает тело auth-функции в `resources/app/out/main.js` (regex по минифицированному коду — переживает переименование переменных между сборками) и добавляет fallback имени пользователя в `extensions/antigravity/dist/extension.js` — как это делает оригинал.

- Перед первой правкой создаётся бэкап `<файл>.ag_backup`; откат (пункт 5) восстанавливает файлы из бэкапов побайтово.
- Если сигнатура не найдена (вышла новая версия IDE) — скрипт честно говорит об этом и **не трогает** файлы.

### 2. DNS-пин (сетевая блокировка)

Запросы агента идут на `daily-cloudcode-pa.googleapis.com`, `generativelanguage.googleapis.com`, а у IDE — на `cloudcode-pa.googleapis.com`. Из России эти адреса напрямую не доступны.

Скрипт опрашивает «анблок»-DNS-сервисы (geohide.ru, comss.one, dns-ai.ru — по UDP и по DoH) и прописывает живые подменённые адреса в `/etc/hosts` (между маркерами `AG_UNLOCKER_HOSTS_*`).

- **Работает и при включённом VPN**: DoH-запросы идут мимо туннеля через физический интерфейс, поэтому сервисы видят российский адрес и отдают подмену. Выключать VPN больше не нужно.
- **DoH устойчив к перехвату DNS провайдером**: запросы — обычный HTTPS на 443 порт, а не UDP/53.
- **Каждый кандидат проходит боевую пробу** (реальный HTTPS-запрос к Google через него), пинуются не более двух самых быстрых адресов на домен.

**Как отличается подмена от честного ответа:** ответ провайдера сравнивается с эталонным резолвером (8.8.8.8 / 1.1.1.1). Если подсеть ответа не совпадает с эталонной — это прокси.

> ⚠️ Анблок-сервисы подменяют ответы **только клиентам из блокируемого региона** (и только пока живы их узлы — xbox-dns.ru, например, умер в октябре 2026 и из пула выкинут). Если ни один не отдал подмену — скрипт скажет об этом честно; режим с VPN (пункт 2) от этого не зависит.

### 3. Watchdog (авто-репатч после обновлений)

Antigravity обновляется сам и затирает патч. Пункт 6 ставит фонового агента (LaunchAgent на macOS, systemd user service на Linux), который следит за файлами и **восстанавливает патч через ~5 секунд после апдейта**, попутно обновляя протухший hosts-пин. Правила честные: файл патчится только когда он дописан до конца (стабилен два тика), неизвестная новая сборка не трогается вообще (скрипт скажет «обнови анлокер» вместо порчи файлов), а пункт 5 (полный откат) выключает watchdog совсем.

## Требования

**macOS:** 12+ (Apple Silicon или Intel), Antigravity `.dmg` с [antigravity.google/download](https://antigravity.google/download)

**Linux:** x86_64, Antigravity `.deb` / `.rpm` / `tar.gz` (AppImage не поддерживается — файл временный, патч невозможен; tar.gz — просто распакуй куда удобно, скрипт найдёт)

Общее: Google-аккаунт (любой страны).

## Установка

**Шаг 1.** Скачай и установи Antigravity: https://antigravity.google/download

> ⚠️ **macOS:** после установки **сразу запусти приложение один раз вручную** и закрой. Если скачал через браузер — Safari/Chrome ставят карантинный флаг, из-за которого macOS запускает приложение из временной read-only копии (App Translocation), и патч не попадает в настоящие файлы. Скрипт снимает карантин автоматически, но первый запуск лучше сделать после него.

**Шаг 2.** Скачай скрипт для своей платформы:

```bash
# macOS
curl -sLO https://github.com/Asalio123/antigravity-unlocker/raw/main/macos/ag_unlocker_mac.sh
# Linux
curl -sLO https://github.com/Asalio123/antigravity-unlocker/raw/main/linux/ag_unlocker_linux.sh
```

или скачай нужный файл из этого репозитория кнопкой **Code → Download ZIP**.

**Шаг 3.** Запусти:

```bash
sudo bash ag_unlocker_mac.sh    # macOS
sudo bash ag_unlocker_linux.sh  # Linux
```

> macOS: скрипт просит права администратора, потому что пишет в `/Applications` и `/etc/hosts`.
> Linux: нужен root по той же причине; дополнительно нужен `dig` — на Debian/Ubuntu `sudo apt install -y dnsutils`, на Fedora/RHEL `sudo dnf install -y bind-utils`.
>
> ⚠️ **Linux, AppImage:** в AppImage-версии патч невозможен (файл временный) — ставь `.deb`/`.rpm` или распакуй `tar.gz`.

## Использование

```
===== Antigravity анлокер для macOS =====
 1) Разблокировать (патч + DNS-пин, все найденные бандлы)
 2) Только патч (для режима с VPN)
 3) Обновить DNS-пин (работает и при включённом VPN)
 4) Статус / диагностика
 5) Полный откат (снять патч и вернуть всё как было)
 6) Watchdog: включить/выключить авто-репатч после обновлений
 0) Выход
```

### Какой пункт выбрать

| Ситуация | Пункт |
|---|---|
| У меня есть VPN, просто Antigravity не работает | **2** — патч убирает клиентскую проверку региона, VPN даёт зарубежный IP |
| Хочу пользоваться **без VPN** вообще | **1** — патч + DNS-пин (пин работает при любом состоянии VPN) |
| Перестало работать без VPN (поменялись прокси-IP) | **3** — обновить пин (с включённым watchdog это происходит само) |
| Чтобы патч переживал автообновления | **6** — включить watchdog |
| Проверить, что установлено и пропатчено | **4** |
| Вернуть всё как было | **5** — полный откат, всё обратимо |

После патча: запусти Antigravity, войди в Google-аккаунт — гейт больше не сработает.

## Если что-то не работает

<details>
<summary><b>«Приложение "Antigravity.app" повреждено и его не удается открыть»</b></summary>

Так macOS реагирует на изменение подписанного приложения. Начиная с macOS 13 права на переподписку приложений выдаются отдельно:

1. В диалоге нажми **«Отменить»** (не «Переместить в Корзину»!).
2. Открой **Системные настройки → Конфиденциальность и безопасность → Управление приложениями**.
3. Включи свой терминал (или добавь его кнопкой «+»).
4. Запусти скрипт заново — пункт 2. Он переподпишет приложение ad-hoc, и запуск из Finder/Launchpad заработает.
</details>

<details>
<summary><b>IDE открывается, логин проходит, но запросы падают с «Agent execution terminated due to error»</b></summary>

Это сетевая часть: трафик агента не доходит до Google. Нужен DNS-пин — **пункт 3 при выключенном VPN**, затем Retry в диалоге ошибки.
</details>

<details>
<summary><b>DNS-пин пишет «Ни один провайдер не отдал подменённые адреса»</b></summary>

Анблок-DNS подменяют ответы **только клиентам из блокируемого региона** (VPN тут не при чём — DoH-запросы идут мимо туннеля). Если ни один не подменяет: либо ты не в регионе подмены, либо узлы сервисов сейчас лежат. Обходной путь: пункт 2 (патч) + любой VPN с не-RU выходом.
</details>

<details>
<summary><b>Скрипт пишет «строка не найдена — новая сборка? Пропускаю» / «сигнатура main.js не найдена»</b></summary>

Google выпустили обновление, в котором изменился код. Жди обновления скрипта или заведи issue. Приложение при этом остаётся рабочим — скрипт не трогает то, что не понимает.
</details>

<details>
<summary><b>IDE: «обнаружена старая версия патча в main.js»</b></summary>

IDE уже патчилась другой/старой версией анлокера (Windows-оригиналом или ранней сборкой). Переустанови IDE чисто (удали и поставь заново с antigravity.google/download) и повтори пункт 1 или 2.
</details>

<details>
<summary><b>После обновления Antigravity анлокер перестал работать</b></summary>

Обновление затирает пропатченные файлы оригинальными — это нормально. Просто запусти скрипт ещё раз (пункт 1 или 2).
</details>

Честно о границах порта:

| Компонент оригинала | Статус | Причина |
|---|---|---|
| Байтовый патч Language Server | ✅ перенесён | |

| Локальный DNS-релей с watchdog | ⚙️ частично | Релей не нужен (хватает пина), watchdog с авто-репатчем перенесён — пункт 6 |
| IPv6 prefixpolicy-хак | ❌ не нужен | На macOS hosts перекрывает DNS для обеих адресных семей |
| Патчер Gemini CLI | ❌ | В оригинале помечен deprecated |

## Безопасность

Сам механизм обхода нашли авторы оригинала — без их работы этого порта не было бы. Оригинал распространяется как закрытый `.exe` с лицензионными ключами через Telegram, и часть адресов прокси намеренно скрыта из исходников — это выбор автора, и он имеет на него право.

Этот порт — для тех, кто предпочитает запускать только то, что можно прочитать целиком:

- **Весь код открыт** — bash-скрипты (~850 строк каждый), никаких бинарников в репозитории.
- **Ничего не отправляет и не собирает**: ни токенов, ни статистики, ни ключей. Из сети — только DNS-запросы и TCP-пробы в пункте 3.
- **Работает только с файлами Antigravity** (бинари и JS внутри установки), `/etc/hosts` и штатным `codesign`.
- **Без ключей**: используется только DNS-метод, работающий без лицензий.
- **Обратимо**: пункт 5 возвращает кодовые байты бинарей (на Linux — побайтово целиком) и JS-файлы побайтово (из бэкапов `.ag_backup`), чистит hosts. Единственный нюанс macOS: подпись бинарей после отката остаётся ad-hoc — оригинальную подпись Apple может вернуть только переустановка приложения, на работу это не влияет.

В любом случае не запускай ничего вслепую — этот скрипт небольшой и читается глазами за десять минут.
